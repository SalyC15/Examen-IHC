# Hallazgos y backlog

## Registro de hallazgos

Completar tras sesiones. Cada hallazgo debe incluir código, tarea, evidencia observable (cita o conducta), severidad 0–4, alcance, principio afectado y acción sugerida.

## Backlog inicial basado en inspección

| Prioridad | Hipótesis a validar | Criterio de cierre |
|---|---|---|
| P1 | Usuario puede no advertir eliminación accidental de una línea | Sesión demuestra recuperación o se implementa deshacer con feedback |
| P1 | Diálogo puede no explicar que el prototipo no procesa pago | Participantes interpretan correctamente el paso siguiente |
| P2 | Persistencia inválida podría vaciar carrito sin explicación | Estado corrupto se detecta y el mensaje no confunde |
| P2 | Contraste de texto auxiliar requiere medición | Todos los textos cumplen contraste elegido o se ajusta paleta |

Priorizar con severidad, frecuencia observada y alcance. Las prioridades son hipótesis de inspección, no frecuencia real.
